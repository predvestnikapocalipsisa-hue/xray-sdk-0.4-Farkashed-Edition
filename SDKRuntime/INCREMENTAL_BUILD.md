# Инкрементальная сборка SDK

Рабочая директория: `C:\X-Ray SDK GUI Rework`.

Для ежедневных изменений используйте **Сборка / Build**, а не **Пересобрать / Rebuild**. MSBuild сохраняет `.obj`, PCH, библиотеки и журналы зависимостей в `output`; удаление этой папки или выбор Rebuild уничтожает возможность переиспользовать результаты. Не меняйте платформу и конфигурацию между последовательными сборками одного SDK.

## Команды

Из PowerShell в корне проекта:

```powershell
# Обычная инкрементальная сборка всего комплекта, Release/x64 по умолчанию.
.\Build-SDK.ps1

# Изменения только в Level Editor: его проект и необходимые зависимости.
.\Build-SDK.ps1 -Module LevelEditor

# Общий интерфейс: проверить архивы и обновить SDKRuntime.dll.
.\Build-SDK.ps1 -Module XrEUI

# Собрать модуль, затем синхронизировать весь имеющийся комплект в установленный SDK.
.\Build-SDK.ps1 -Module LevelEditor -Destination 'D:\SDK\bin'

# Только обновить файлы из существующей сборки, без компиляции.
.\Build-SDK.ps1 -CopyOnly -Destination 'D:\SDK\bin'

# Посмотреть команду и путь копирования, не запускать сборку и не копировать.
.\Build-SDK.ps1 -Module LevelEditor -Destination 'D:\SDK\bin' -Plan
```

Доступны `-Configuration Debug|Development|Release` и `-Platform Win32|x64`. Модуль по умолчанию — `All`. Выбор `Launcher` также проверяет его зависимости, включая редакторы: это штатный корневой проект комплекта.

Для общих архивов (`XrCore`, `XrEUI`, `XrECore` и прочих) команда строит граф `SDKRuntime`, поскольку изменение `.lib` должно попасть в итоговую DLL. Актуальные проекты этого графа переиспользуются. Изменение общего заголовка может обоснованно потребовать компиляции нескольких проектов; при изменении экспортируемого API выбирайте `All`, чтобы также проверить все редакторы.

## Копирование

`BuildedSDK/<platform>_<configuration>` остаётся основным каталогом результатов. `-Destination` синхронизирует Launcher, шесть SDK DLL, сторонние runtime DLL, доступные PDB и библиотеки VC runtime. Уже актуальные файлы пропускаются. Если байты совпадают, но исходная дата изменилась, дата установленного файла сохраняется. Пользовательские настройки, данные, сцены и посторонние файлы не удаляются.

Перед копированием проверяется наличие обязательных файлов всего комплекта. Для первой сборки в пустом каталоге используйте `All`. При ошибке MSBuild синхронизация не запускается. Для обновления DLL закройте процессы редакторов, удерживающие эти файлы.

## Исправление LuaJIT

Старая команда обновляла DLL и импортную библиотеку только при их отсутствии. Из-за этого обычная сборка оставляла устаревшие копии, а удаление файлов / Rebuild казались необходимыми.

Теперь `Build-LuaJIT.ps1`:

- Сравнивает отпечаток исходников, DynASM, сценариев и версии инструментов; при неизменных входах переиспользует готовые DLL и `.lib`.
- Обновляет изменившиеся и восстанавливает отсутствующие копии в каталоге SDK и библиотек.
- Не меняет дату идентичной импортной библиотеки, избегая лишней линковки её потребителей.
- Возвращает ошибку при неудаче LuaJIT, вместо продолжения сборки с устаревшим результатом.
- При явном Clean удаляет только известные продукты выбранной архитектуры, сохраняя другую архитектуру.

Первый запуск после внедрения создаёт проверенный кеш и один раз пересобирает **LuaJIT**, поскольку отпечатка его прежней сборки нет. LuaJIT использует собственный пакетный генератор; при изменении его входов этот компонент собирается целиком. Остальные C++ проекты сохраняют стандартную инкрементальность MSBuild, настройки оптимизации Release не изменены.

## Проверка без сборки

```powershell
.\SDKRuntime\validate_incremental.ps1
python SDKRuntime/validate_layout.py
```

Первая проверка выполняет копирование на временных фиктивных файлах и проверяет восстановление LuaJIT-копий; вторая проверяет XML и граф проектов. Обе не запускают компилятор. Сборка SDK и измерение её времени при внесении этих изменений не проводились.
