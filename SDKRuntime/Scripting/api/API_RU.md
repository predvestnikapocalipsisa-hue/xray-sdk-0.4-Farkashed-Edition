# X-Ray SDK Farkashed Edition: полный справочник API скриптов и аддонов

**Язык: Python. Встроенная среда поставки: CPython 3.13.17, Windows x64.**  

Этот справочник описывает реализованную систему расширения SDK: создание аддонов,
управление их жизненным циклом, операторы, панели, команды редакторов, объекты
сцены, Undo/Redo, события, таймеры, настройки и взаимодействие Python с C++ и Lua.
Сведения о поведении относятся к исходникам этой поставки, а не к предполагаемым
возможностям будущих версий. Формальные сигнатуры также доступны в `xray.pyi`.

## 01. Назначение и границы API

Аддон — пользовательское расширение редактора. Он может добавлять команды в меню
Scripts, собственные окна, горячие клавиши, обработчики событий и периодические
задачи. В Level Editor он также может создавать и изменять поддерживаемые объекты.

`import xray` предоставляет единую точку доступа к SDK. Сам модуль реализован на
Python и вызывает проверяемый нативный мост из `SDKRuntime.dll`. Из Python нельзя
получить указатель на `CCustomObject` через публичный API: вместо него возвращается
проверяемый числовой дескриптор, действующий в текущем процессе.

| Возможность | Level Editor | Actor Editor | Particle Editor | Shader Editor |
|---|---|---|---|---|
| Загрузка `.xpy`, менеджер, консоль | Да | Да | Да | Да |
| Операторы, панели и виджеты | Да | Да | Да | Да |
| Таймеры и общие события | Да | Да | Да | Да |
| Настройки аддона | Да | Да | Да | Да |
| Вызов зарегистрированных нативных команд | Да | Да | Да | Да |
| Изолированная Lua-среда аддона | Да | Да | Да | Да |
| `scene` и свойства `Object` из этого документа | Да | Нет | Нет | Нет |
| Автоматическая транзакция сцены оператора | Да | Нет | Нет | Нет |

Набор нативных команд различается между редакторами. Наличие командного моста
не означает, что каждому внутреннему полю редактора уже соответствует Python-свойство.
В частности, API 1 не предоставляет прямой редактор вершин, материалов, параметров
спавна или полного набора настроек источников света.

Подход к операторам и панелям похож на Blender, но модуль `bpy` здесь отсутствует.
Аддоны Blender нельзя перенести простым переименованием `.py` в `.xpy`.

## 02. Устройство среды и расположение файлов

Для установленного SDK корневая папка — `X-Ray SDK`:

```text
X-Ray SDK\
├── addons\                          Пользовательские расширения
│   ├── hello_sdk.xpy                 Однофайловый пример
│   └── scene_tools\                 Пакетный пример
│       ├── addon.json
│       ├── __init__.xpy
│       └── helpers.xpy
├── settings\
│   ├── addons.json                  Включённые аддоны по редакторам
│   ├── addons\
│   │   └── my_tools.json            Настройки конкретного аддона
│   └── addon-trash\                 Восстанавливаемые удалённые аддоны
└── bins\
    ├── SDKRuntime.dll               Общий хост и C ABI
    ├── LevelEditor.dll              Реализация API сцены
    ├── LuaJIT.dll                   Среда Lua
    ├── python\                     Частная среда CPython
    │   ├── python313.dll
    │   ├── python313.zip
    │   └── ...
    └── scripting\
        ├── xray\
        │   ├── __init__.py          Реализация обёрток API
        │   └── __init__.pyi         Типы пакета для IDE
        └── api\
            ├── API_RU.md            Этот справочник
            ├── README.md            Точка входа в документацию
            ├── xray.pyi             Публичные сигнатуры
            ├── SDKScriptABI.h       Контракт C ABI
            ├── bridge.md            Краткая спецификация моста
            └── lua.md               Краткая спецификация Lua
```

Внутри аддона путь к корню следует получать через `xray.context.sdk_root`.
Текущая рабочая папка процесса не является надёжным способом найти SDK.

```python
from pathlib import Path
import xray

root: Path = xray.context.sdk_root
report = root / "settings" / "my_report.json"
xray.log("Путь отчёта:", report)
```

Python запускается внутри процесса редактора. Он не требует системной установки
Python и не меняет системный PATH. Встроенный путь поиска включает частную папку
Python, архив стандартной библиотеки и `bins/scripting`.

Наличие Python в SDK само по себе не означает наличие `pip`, NumPy или сторонних
пакетов. Бинарные расширения должны соответствовать CPython 3.13 и архитектуре x64.
Зависимости аддона из `requires` — другие аддоны SDK, а не пакеты из PyPI.

## 03. Быстрый запуск

1. Создайте `X-Ray SDK\addons\first_addon.xpy` в кодировке UTF-8.
2. Вставьте код ниже.
3. Откройте **Scripts → Add-on Manager**.
4. Нажмите **Refresh**, затем **Enable** у «Мой первый аддон».
5. В меню **Scripts** выберите «Проверить подключение».
6. Результат появится в **Scripts → Python Console** и журнале SDK.

```python
addon_info = {
    "id": "first_addon",
    "name": "Мой первый аддон",
    "version": "1.0.0",
    "api_version": 1,
    "description": "Проверка работы Python API SDK",
}

import xray


def hello(context):
    xray.log("Аддон работает. Редактор:", context.editor)
    xray.log("Корневая папка:", context.sdk_root)
    xray.log("Версия API:", xray.API_VERSION)


def register():
    xray.operator(
        "first_addon.hello",
        "Проверить подключение",
        undo=False,
        shortcut="CTRL+SHIFT+H",
    )(hello)


def unregister():
    pass
```

После редактирования файла нажмите **Reload** в менеджере. Простое сохранение
исходника не перезагружает уже импортированный модуль автоматически.

Если нужна только проверка без установки, откройте Python Console и выполните:

```python
import xray
xray.log("Редактор:", xray.context.editor)
xray.log("API:", xray.app.api_version)
```

## 04. Формат .xpy и правила Python

`.xpy` — обычный исходный текст Python, читаемый загрузчиком SDK. Здесь нет
шифрования, отдельного языка выражений или компиляции Python в C++/Lua.
Мост вызывает C++ и Lua во время выполнения.

Допускаются стандартные конструкции Python: функции, классы, исключения,
контекстные менеджеры, аннотации типов, генераторы и модули стандартной библиотеки.
Скрипт должен быть синтаксически совместим с поставляемой версией CPython.

Пользовательские исходники аддонов используют `.xpy`. Внутренний пакет `xray`
и стандартная библиотека сохраняют штатные расширения Python. Разовый запуск
через меню принимает `.xpy`, установка через менеджер — `.xpy` или `.zip`.

Кодировка — UTF-8; загрузчик также принимает UTF-8 с BOM. Отступы имеют обычное
значение Python. Для нового кода удобно использовать четыре пробела.

Особенности импорта:

- В пакетном аддоне используйте `from .helpers import function` для `helpers.xpy`.
- Вложенный пакет должен содержать `__init__.xpy`.
- Пользовательский поиск `.xpy` действует для путей внутри папки `addons`.
- Каждый аддон импортируется под внутренним именем `_xray_addon_<id>`.
- Не используйте внутреннее имя для связи между аддонами: оно не является
  публичным интерфейсом обмена.
- Флаг `sys.dont_write_bytecode` установлен хостом; обычная работа аддонов не
  требует распространять `.pyc`.

Для ресурсов рядом с файлом аддона:

```python
from pathlib import Path

ADDON_DIRECTORY = Path(__file__).resolve().parent
PRESET = ADDON_DIRECTORY / "presets" / "default.json"
```

Этот способ работает и в пакетном аддоне. Для однофайлового аддона родителем
будет общая папка `addons`, поэтому собственные ресурсы лучше хранить в пакете.

## 05. Однофайловый аддон и addon_info

Однофайловый аддон содержит метаданные в переменной `addon_info` и функцию
`register()`. Функция `unregister()` рекомендуется, но загрузчик допускает её
отсутствие. Сам `addon_info` может отсутствовать: тогда применяются значения
по умолчанию. Для распространяемого расширения метаданные следует задавать явно.

```python
addon_info = {
    "id": "selection_tools",
    "name": "Инструменты выделения",
    "version": "1.0.0",
    "api_version": 1,
    "description": "Пакетная обработка выбранных объектов",
    "editors": ["level"],
    "requires": [],
}
```

| Поле | Тип | Значение по умолчанию / поведение |
|---|---|---|
| `id` | `str` | Имя файла без расширения; идентификатор аддона |
| `name` | `str` | В интерфейсе при отсутствии используется ID |
| `version` | Обычно `str` | В интерфейсе при отсутствии показывается `1.0` |
| `api_version` | Число `1` | При отсутствии принимается API 1 |
| `description` | `str` | При отсутствии пустая строка |
| `editors` | `list[str]` | Все четыре редактора |
| `requires` | `list[str]` | Пустой список |

Правило ID аддона: `[a-z][a-z0-9_]{0,63}`. Первая буква — строчная латинская,
далее строчные латинские буквы, цифры и `_`; длина от 1 до 64 символов.
Например: `my_tools`, `scene_cleanup2`. Пробелы, дефисы и кириллица в ID не подходят.
В отображаемом `name` кириллица разрешена.

При обнаружении выключенного однофайлового аддона загрузчик разбирает AST и
извлекает буквальное значение `addon_info`, не выполняя исходник. Поэтому пишите
обычный словарь литералов, а не результат функции:

```python
# Поддерживаемый способ:
addon_info = {"id": "example", "name": "Пример", "api_version": 1}

# Для метаданных загрузчика так делать не следует:
# addon_info = make_metadata()
# addon_info = dict(id="example")
```

Используйте обычное присваивание `addon_info = ...`, без вычисляемых выражений и
аннотированного присваивания. Это соответствует фактическому способу извлечения
метаданных текущим загрузчиком.

Метаданные сами по себе не выполняют регистрацию. Команды и панели появляются
после включения аддона и успешного завершения `register()`.

## 06. Пакетный аддон и addon.json

Когда аддон состоит из нескольких модулей, используйте отдельную папку:

```text
addons/
  building_tools/
    addon.json
    __init__.xpy
    operators.xpy
    panels.xpy
    math_tools.xpy
    presets/
      default.json
```

Пример `addon.json`:

```json
{
  "id": "building_tools",
  "name": "Инструменты построения",
  "version": "1.0.0",
  "api_version": 1,
  "entry": "__init__.xpy",
  "description": "Операторы для Level Editor",
  "editors": ["level"],
  "requires": []
}
```

Для пакета основным источником метаданных является `addon.json`. Если `entry`
не задан, используется `__init__.xpy`. Точка входа должна существовать, иметь
расширение `.xpy` и после разрешения пути оставаться внутри папки аддона.
При отсутствии `id` берётся `Path.stem` папки; рекомендуется явно указывать ID
и называть папку так же.

Пример точки входа:

```python
import xray
from .operators import BuildOperator
from .panels import BuildPanel

CLASSES = (BuildOperator, BuildPanel)


def register():
    for cls in CLASSES:
        xray.utils.register_class(cls)


def unregister():
    for cls in reversed(CLASSES):
        xray.utils.unregister_class(cls)
```

В дочернем модуле `operators.xpy`:

```python
import xray
from .math_tools import raise_position


class BuildOperator(xray.Operator):
    bl_idname = "building_tools.raise"
    bl_label = "Поднять выделение"

    def execute(self, context):
        for obj in context.selected_objects:
            obj.position = raise_position(obj.position, 1.0)
```

В `math_tools.xpy`:

```python
def raise_position(position, distance):
    x, y, z = position
    return (x, y + distance, z)
```

Зависимости перечисляются по ID установленных аддонов:

```json
{
  "id": "dependent_tools",
  "name": "Дополнительные инструменты",
  "api_version": 1,
  "editors": ["level"],
  "requires": ["building_tools"]
}
```

Сначала включаются зависимости. Отсутствующая зависимость, циклическая цепочка
или неподдерживаемый редактор приводят к ошибке включения. Если включение
зависимого аддона завершилось неудачно, вновь включённые для него зависимости
отключаются; ранее включённые аддоны сохраняются.

Загрузчик не реализует ограничения вида `building_tools>=2.0`, разрешение версий
или автоматическую загрузку зависимостей из интернета. Поле `version` — метаданные.

## 07. Жизненный цикл и принадлежность ресурсов

Обычная последовательность:

```text
Refresh → чтение метаданных → запись в менеджере (Disabled)
Enable → включение зависимостей → импорт исходника → register() → Enabled
Disable → unregister() → удаление ресурсов владельца → Disabled
Reload → Disable → повторное обнаружение → новый импорт → register()
Uninstall → Disable → перенос исходников в settings/addon-trash
Закрытие редактора → shutdown → отключение аддонов → завершение Python
```

У каждого callback есть владелец. Регистрация оператора, панели, события, таймера,
обращение к настройкам и Lua из `register()` или callback аддона относятся к его ID.
Интерактивная консоль и разовые скрипты используют владельца `console`.

После отключения аддона хост автоматически удаляет:

- Его операторы, панели и нативные записи меню.
- Его подписки и таймеры.
- Зарегистрированные экземпляры классов.
- Основной Python-модуль и импортированные дочерние модули с его префиксом.
- Его изолированное состояние Lua.

При ошибке первоначальной регистрации выполняется очистка частично созданных
ресурсов без вызова пользовательского `unregister()`. При обычном отключении
`unregister()` вызывается, если он существует. Автоматическая очистка нужна и
тогда, когда эта функция завершилась исключением.

Собственные внешние ресурсы следует закрывать самому: открытые файлы, сокеты,
запущенные процессы, потоки и сторонние подписки не становятся ресурсами SDK
только потому, что созданы в аддоне. Модули сторонних библиотек без префикса
аддона также не обязаны выгружаться при Reload.

`register()` удобно использовать для загрузки настроек и регистрации интерфейса.
Не изменяйте сцену автоматически при одном лишь включении расширения, если это
не является понятным назначением аддона. Операции пользователя оформляйте
отдельными операторами.

На стадии закрытия редактора мост разрешает только логирование и удаление
ресурсов владельца. В `shutdown` и `unregister()` при закрытии не рассчитывайте
на чтение или изменение сцены, запуск Lua и выполнение команд. Сохранение
Python-настроек в файл не требует обращения к сцене, но лучше сохранять их
по явному действию пользователя до завершения редактора.

## 08. Менеджер аддонов и xray.addons

В **Scripts → Add-on Manager** доступны Refresh, Install .xpy / .zip, New add-on
и Open folder. Для каждой записи доступны Enable/Disable, Reload и Uninstall.
Ошибка метаданных или регистрации отображается в записи и журнале.

### `addons.directory: pathlib.Path`

Папка обнаружения аддонов: `<sdk_root>/addons`. Используйте для чтения пути.
Изменение этого атрибута не является штатным способом перенастроить SDK.

### `addons.records: dict[str, dict]`

Текущие записи менеджера, индексированные по ID. Подходят для диагностики:

```python
for identifier, record in xray.addons.records.items():
    xray.log(identifier, record.get("enabled"), record.get("error", ""))
```

Запись содержит `id`, `info`, `path`, `entry`, `requires`, `editors`, `enabled`,
`error`. Для некорректной записи устанавливается `invalid`; после загрузки
может присутствовать `module`, при ошибках — `failures`. Это оперативное
состояние менеджера, не формат собственного хранилища аддона. Не меняйте
`enabled` вручную: так пропускается реальное включение/отключение ресурсов.

### `addons.refresh() -> None`

Перечитывает папку, добавляет новые записи и удаляет исчезнувшие. Имена,
начинающиеся с точки, пропускаются. Метаданные активного аддона не заменяют
его работающий модуль. Для применения исходников нужен `reload()`.

Некорректные записи получают служебный ID вида `invalid_<hash>` и остаются
видимыми для диагностики. Два аддона с одинаковым ID не следует устанавливать
одновременно.

### `addons.enable(identifier: str, *, persist: bool = True) -> None`

Включает аддон и его зависимости. Уже включённая запись повторно не загружается.
`persist=True` сохраняет список включённых аддонов для текущего редактора.
`persist=False` используется, когда включение не нужно записывать как отдельное
пользовательское изменение, например при восстановлении состояния хостом.

```python
xray.addons.refresh()
xray.addons.enable("hello_sdk")
```

Неизвестный ID может вызвать `KeyError`, ошибки метаданных — `ValueError`,
неудачная регистрация — `RuntimeError`. Подробный traceback выводится в журнал.

### `addons.disable(identifier: str) -> None`

Отключает и сохраняет состояние. Если от аддона зависят активные расширения,
сначала необходимо отключить их. Не вызывайте отключение собственного аддона
из середины его операции: управление жизненным циклом удобнее выполнять
из менеджера или консоли, когда callback уже завершён.

### `addons.reload(identifier: str) -> None`

Отключает модуль, обновляет запись, сбрасывает кеш поиска импортов и, если
аддон был включён, загружает свежий код. Выключенный аддон после Reload
остаётся выключенным. Для зависимости с активными потребителями Reload
запрещён до их отключения.

### `addons.install(filename: str | Path) -> str`

Устанавливает `.xpy` или ZIP, возвращает ID. Установленный аддон не включается
автоматически. Можно передать абсолютный путь:

```python
identifier = xray.addons.install(r"E:\Downloads\new_tools.zip")
xray.log("Установлено:", identifier)
```

Проверяются состав архива, пути, символьные ссылки, размер и манифест.
Максимум — 1024 элемента ZIP и 32 МиБ суммарного заявленного распакованного
размера. Существующий ID или папка назначения не перезаписываются.

### `addons.uninstall(identifier: str) -> None`

Отключает аддон и переносит его исходник/папку в
`settings/addon-trash/<время>-<имя>`. Это не безвозвратное удаление.
Настройки `settings/addons/<id>.json` не удаляются этой операцией.

### `addons.create_template() -> Path`

Создаёт свободный файл `my_addon_1.xpy`, `my_addon_2.xpy` и т. д., обновляет
список и открывает папку в Проводнике. Возвращает путь к файлу. Включение
шаблона выполняется отдельно.

### `addons.open_folder() -> None`

Открывает папку `addons` штатным механизмом Windows.

## 09. Общие типы, контекст и приложение

### Версия API

```python
xray.API_VERSION          # 1
xray.app.api_version      # 1
```

Манифест с несовместимым `api_version` отклоняется до выполнения исходника.
Версия API и версия Python — разные понятия.

### `Vector3`

В типовых объявлениях это `tuple[float, float, float]`: `(x, y, z)`.
Геттеры трансформации возвращают кортежи. Сеттеры ожидают последовательность
из трёх чисел. Для числового моста допускаются только конечные значения.
`NaN`, `+inf`, `-inf` не подходят.

### `JSON`

В файле типов используется обобщённое обозначение JSON-совместимых данных.
Для переносимого кода используйте `None`, `bool`, конечные числа, строки,
списки и словари со строковыми ключами. Объекты сцены, функции, `Path` и
множества нужно преобразовывать явно. Ограничения преобразования Lua
дополнительно описаны в разделе 22.

### `xray.context` и `xray.Context`

`context` — общий объект контекста. `Context` — его публичный тип/псевдоним,
доступный для аннотаций. Создавать собственный Context обычно не требуется.

| Свойство | Тип | Содержание |
|---|---|---|
| `context.editor` | `str` | `level`, `actor`, `particle` или `shader` |
| `context.sdk_root` | `Path` | Абсолютный корень SDK |
| `context.scene` | Объект API сцены | Та же точка доступа, что `xray.scene` |
| `context.selected_objects` | `list[Object]` | Выделение сцены Level Editor |

```python
def execute(context):
    if context.editor != "level":
        xray.log("Эта операция предназначена для Level Editor")
        return
    xray.log("Выбрано объектов:", len(context.selected_objects))
```

Контекст не является копией сцены. При каждом запросе выделения получается
актуальный список. В API 1 отсутствуют `context.active_object`, `context.mode`,
`context.window_manager` и переопределения контекста в стиле `bpy`.

### `xray.app`

`app.events` и `app.timers` — те же экземпляры, что `xray.events` и `xray.timers`.
Они позволяют писать код в стиле `xray.app.timers.register(...)`.

`app.request_exit() -> None` отправляет обычный запрос закрытия окна через
очередь Windows. Он не завершает Python посреди callback и не отменяет
обычную проверку несохранённой сцены. Пользователь может отказаться от
закрытия в диалоге редактора. Для обычных аддонов этот вызов не требуется.

## 10. Операторы и горячие клавиши

Оператор — зарегистрированное действие, доступное в меню Scripts, по горячей
клавише и через `xray.ops.call`. Он получает один аргумент — контекст.

```text
operator(
    idname: str,
    label: str | None = None,
    *,
    undo: bool = True,
    shortcut: str = "",
) -> decorator
```

`idname` должен быть непустым и уникальным среди операторов. Рекомендуемый
шаблон — `<id_аддона>.<действие>`, например `my_tools.move_up`. Строгое правило
ID аддона из манифеста не является отдельным валидатором ID оператора, но
согласованные латинские имена упрощают сопровождение.

`label` — надпись в меню и заголовок транзакции. Если не задан, используется ID.
`undo=True` автоматически оборачивает callback в транзакцию Level Editor.
В других редакторах callback вызывается без этой транзакции.

Регистрация из `register()`:

```python
def move_up(context):
    for obj in context.selected_objects:
        x, y, z = obj.position
        obj.position = (x, y + 1.0, z)


def register():
    xray.operator("my_tools.move_up", "Поднять на 1", undo=True)(move_up)
```

Возможна и декораторная запись:

```python
@xray.operator("my_tools.report", "Отчёт", undo=False)
def report(context):
    xray.log(context.editor)
```

Такой декоратор выполняет регистрацию во время импорта. Для крупных аддонов
предпочтительнее явная регистрация в `register()`: её легче организовать и
проверить. При загрузке аддона обе формы получают правильного владельца.

### Возвращаемое значение

Результат callback доступен через `ops.call`. Допускается обычное Python-значение.
`{"FINISHED"}` из примеров — пользовательское соглашение, а не обязательный
код состояния. `{"CANCELLED"}` не отменяет транзакцию автоматически.
Если требуется откат уже сделанных изменений, должно возникнуть исключение,
вышедшее из тела транзакции.

Вызов через хост перехватывает исключения оператора, печатает traceback и
возвращает `None`. Не рассчитывайте, что `try/except` вокруг `ops.call()`
получит исходное исключение callback.

### Горячие клавиши

Поддерживаются CTRL, SHIFT, ALT и одна латинская буква A–Z. Примеры:

```python
shortcut="CTRL+SHIFT+U"
shortcut="ALT+R"
shortcut="CTRL+ALT+M"
```

Строка переводится в верхний регистр, пробелы удаляются. F-клавиши, цифры,
мышь, последовательности клавиш и пользовательская система keymap не
реализованы. Во время ввода текста сочетания аддонов не обрабатываются.
Модификаторы сравниваются точно: CTRL+U не эквивалентно CTRL+SHIFT+U.

Глобального диспетчера конфликтов нет. Выбирайте редко используемые
сочетания; не назначайте нескольким операторам одинаковое сочетание.

## 11. Классовая регистрация

### `xray.Operator`

Базовый класс оператора:

```python
class RaiseSelection(xray.Operator):
    bl_idname = "my_tools.raise_selection"
    bl_label = "Поднять выделение"
    bl_options = {"UNDO"}
    bl_shortcut = "CTRL+SHIFT+U"

    def execute(self, context):
        for obj in context.selected_objects:
            x, y, z = obj.position
            obj.position = (x, y + 1.0, z)
        return {"FINISHED"}
```

| Атрибут | Значение по умолчанию | Назначение |
|---|---|---|
| `bl_idname` | `""` | Непустой уникальный ID |
| `bl_label` | `""` | Название; обёртка может использовать ID |
| `bl_options` | `{"UNDO"}` | Наличие строки `UNDO` включает транзакцию |
| `bl_shortcut` | `""` | Сочетание клавиш |

Для команды Undo или загрузки сцены задайте `bl_options = set()`, поскольку
эти команды нельзя выполнять внутри автоматической транзакции.
Остальные строки в `bl_options` не добавляют возможностей API.

### `xray.Panel`

```python
class InfoPanel(xray.Panel):
    bl_idname = "my_tools.info"
    bl_label = "Информация о сцене"

    def draw(self, context):
        xray.ui.text("Редактор: " + context.editor)
        xray.ui.text("Выбрано: " + str(len(context.selected_objects)))
```

Класс панели использует `bl_idname`, `bl_label` и `draw(self, context)`.
Свойства Blender `bl_space_type`, `bl_region_type`, `bl_category`, `poll`
не участвуют в размещении или проверках этой системы.

### `utils.register_class(cls) -> None`

Создаёт экземпляр без аргументов и регистрирует его метод `execute` или `draw`.
Один класс нельзя зарегистрировать дважды. Поддерживаются только наследники
`xray.Operator` и `xray.Panel`.

### `utils.unregister_class(cls) -> None`

Удаляет регистрацию класса и перестраивает нативные записи остальных
операторов/панелей того же владельца. Передавайте ранее зарегистрированный
класс, иначе возможен `KeyError`.

Техническая особенность API 1: при перестройке вызывается удаление нативных
ресурсов владельца, которое также сбрасывает его Lua-состояние. Поэтому
не храните критически важные данные исключительно в Lua между выборочными
вызовами `unregister_class`; при необходимости восстановите Lua-функции.

```python
CLASSES = (RaiseSelection, InfoPanel)


def register():
    for cls in CLASSES:
        xray.utils.register_class(cls)


def unregister():
    for cls in reversed(CLASSES):
        xray.utils.unregister_class(cls)
```

## 12. Панели и модель интерфейса

```text
panel(idname: str, label: str | None = None) -> decorator
```

Функциональная панель получает `context`, как классовая:

```python
offset = 1.0


def draw_tools(context):
    global offset
    offset = xray.ui.input_float("Смещение", offset)
    xray.ui.operator("my_tools.move_up", "Выполнить")


def register():
    xray.panel("my_tools.tools", "Мои инструменты")(draw_tools)
```

Каждая панель — окно ImGui, которым владеет хост. Оно появляется при
регистрации, может быть закрыто крестиком и открыто снова через
**Scripts → Panels**. Закрытие окна не отключает аддон.

Интерфейс имеет непосредственную модель отрисовки: каждый кадр `draw()`
описывает актуальный набор виджетов. Их значения необходимо хранить в
переменных или экземпляре панели. Геттеры ввода возвращают текущее значение,
а не пару `(изменилось, значение)`.

```python
class OptionsPanel(xray.Panel):
    bl_idname = "my_tools.options"
    bl_label = "Настройки инструмента"

    def __init__(self):
        self.enabled = True
        self.distance = 1.0

    def draw(self, context):
        self.enabled = xray.ui.checkbox("Активно", self.enabled)
        self.distance = xray.ui.input_float("Шаг", self.distance)
```

Виджеты можно вызывать только во время `draw`. Вызов из консоли, таймера,
`register()` или обычного оператора вне отрисовки вызывает RuntimeError.
Хост сам вызывает Begin/End окна и завершает его даже при исключении
Python-callback. Публичных `ui.begin()`/`ui.end()` нет.

Не меняйте сцену на каждом кадре только потому, что панель видима. Связывайте
изменение с кнопкой/оператором. Для тяжёлых отчётов сохраняйте результат
между кадрами и обновляйте по запросу или событию.

## 13. Полный справочник виджетов

Все функции ниже доступны как методы `xray.ui`.

### `text(value: object) -> None` и `label(value: object) -> None`

Выводят текст. Значение приводится к строке. `label` — псевдоним `text`.
Строка передаётся в `TextUnformatted`, поэтому `%` не является форматом printf.

```python
xray.ui.text("Обработка: 50%")
xray.ui.label(f"Объектов: {len(context.selected_objects)}")
```

### `button(label: str) -> bool`

Возвращает `True` в кадре нажатия.

```python
if xray.ui.button("Обновить отчёт"):
    xray.log("Пользователь запросил обновление")
```

### `checkbox(label: str, value: bool) -> bool`

Возвращает актуальное состояние флажка. Всегда присваивайте результат:

```python
self.only_selected = xray.ui.checkbox("Только выделенные", self.only_selected)
```

### `input_float(label, value, step=0.1, fast_step=1.0) -> float`

Поле числового ввода. Значение, шаг и ускоренный шаг передаются в InputFloat
ImGui. Внутри виджета используется 32-битный `float`; не ожидайте сохранения
всех разрядов Python `float`.

```python
self.distance = xray.ui.input_float("Расстояние", self.distance, 0.25, 2.0)
```

### `slider_float(label, value, minimum, maximum) -> float`

Ползунок. При `minimum > maximum` Python-обёртка выбрасывает ValueError.
Для осмысленного интерфейса задавайте конечные значения и нормальный диапазон.

```python
self.factor = xray.ui.slider_float("Множитель", self.factor, 0.1, 5.0)
```

### `input_text(label: str, value: str) -> str`

Однострочное текстовое поле. При входе строка не должна превышать 4094 байта
UTF-8. Это ограничение по байтам, а не по количеству букв: кириллица занимает
несколько байтов. Нативный буфер — 4096 байт. Строки с NUL или разделителем
`\x1f` не подходят для этого вызова.

```python
self.prefix = xray.ui.input_text("Префикс", self.prefix)
```

### `separator() -> None`

Горизонтальный разделитель между группами элементов.

### `same_line() -> None`

Располагает следующий виджет в той же строке.

```python
if xray.ui.button("Применить##primary"):
    xray.ops.call("my_tools.apply")
xray.ui.same_line()
if xray.ui.button("Сбросить##primary"):
    self.distance = 1.0
```

### `collapsing_header(label: str) -> bool`

Возвращает открытое состояние секции. Для него не нужен отдельный End:

```python
if xray.ui.collapsing_header("Дополнительно"):
    xray.ui.text("Дополнительные параметры")
```

### `operator(idname: str, label: str | None = None) -> Any`

Рисует кнопку зарегистрированного оператора и при нажатии вызывает его.
Если текст не задан, берётся подпись оператора. Результат — результат
оператора при нажатии, иначе `None`. Неизвестный ID вызывает KeyError.

```python
xray.ui.operator("my_tools.move_up", "Поднять")
```

### Уникальные ID виджетов

ImGui различает элементы по меткам. При повторяющихся кнопках задавайте
скрытую часть после `##`:

```python
for index, title in enumerate(("Первый", "Второй", "Третий")):
    if xray.ui.button(f"Выбрать {title}##row_{index}"):
        xray.log("Строка:", index)
```

Публичные контейнеры row/column, таблицы, деревья свойств, цветовые поля,
выбор файла, всплывающие меню и прямой доступ к ImGui API 1 не предоставляет.
Не переносите вызовы `layout.prop` из Blender: здесь используется `xray.ui`.

## 14. Нативные команды и xray.ops

В `ops` находятся два разных способа запуска действий:

| Метод | Что запускает |
|---|---|
| `ops.execute("COMMAND_...", p0, p1)` | Нативную команду текущего редактора |
| `ops.call("my_addon.action")` | Python-оператор, зарегистрированный аддоном |
| `ops.list()` | Возвращает имена нативных команд, не ID Python-операторов |

### `ops.list() -> list[str]`

```python
commands = xray.ops.list()
for name in commands:
    if "SAVE" in name or "UNDO" in name:
        xray.log(name)
```

Это обнаружение имён, не реестр сигнатур. Список не сообщает тип аргументов,
побочные эффекты, требования к выбранному инструменту или наличие диалога.
Если команда нужна для автоматизации, проверьте её реализацию в исходниках
соответствующего редактора.

### `ops.execute(command: str, p0: str | int = 0, p1: str | int = 0) -> str | int`

Принимает имя и два параметра. Целочисленные параметры — uint32:
`0 <= value <= 4294967295`. Строки передаются отдельно от чисел, поэтому
`0` и `"0"` — разные параметры. Дроби, отрицательные числа, списки и указатели
через этот интерфейс не передаются.

```python
# Сначала убедитесь, что команда существует в текущем редакторе.
if "COMMAND_UNDO" in xray.ops.list():
    xray.ops.execute("COMMAND_UNDO")
```

Не выполняйте Undo, Redo, Clear или Load внутри `scene.transaction` и
оператора с автоматическим Undo. Для отдельного оператора Undo:

```python
def undo_last(context):
    return xray.ops.execute("COMMAND_UNDO")


def register():
    xray.operator("my_tools.undo", "Отменить", undo=False)(undo_last)
```

`COMMAND_INITIALIZE`, `COMMAND_DESTROY`, `COMMAND_QUIT`, `COMMAND_EXIT`
недоступны через мост: они могут разрушить интерпретатор во время callback.
Для закрытия существует `xray.app.request_exit()`.

Команды сохраняют обычную семантику редактора: могут открыть диалог,
потребовать выделение, отложить работу до следующего кадра или вернуть
код, специфичный для своей реализации. Успешный возврат моста не означает
универсальное `True` и не гарантирует завершение отложенной операции.

Если команда меняет текущий инструмент с отложенным применением, продолжайте
зависимое действие через таймер в следующем кадре. Не пытайтесь обеспечить
это `time.sleep`: сон блокирует основной поток редактора.

### `ops.call(idname: str) -> Any`

Вызывает Python-оператор в его контексте владельца и с его настройкой Undo.
Параметры пользовательского оператора в API 1 через этот вызов не передаются.
Храните значения в настройках/состоянии аддона или вызывайте внутреннюю
функцию с аргументами, если это собственная реализация.

Избегайте рекурсивного вызова оператора самим собой. Не используйте `ops.call`
как замену прямому вызову функции, когда нужно получить исключение и выполнить
откат внешней транзакции: оболочка оператора перехватывает ошибки callback.

## 15. Сцена и xray.scene

Далее предполагается **Level Editor**, доступная и незаблокированная сцена.
При недоступной/заблокированной сцене нативный backend выдаёт RuntimeError.

### `scene.objects -> list[Object]`

Возвращает новый список обёрток для текущих объектов. Удалённые объекты
исключаются. Порядок не является стабильным пользовательским индексом.
Не сохраняйте «объект №7» как постоянную ссылку.

```python
for obj in xray.scene.objects:
    xray.log(obj.name, obj.class_id, obj.position)
```

### `scene.selected_objects -> list[Object]`

Возвращает текущее выделение. Это то же содержимое, которое доступно через
`context.selected_objects`. Не путайте выделение с одним активным объектом:
отдельного публичного `active_object` в API 1 нет.

```python
selection = xray.scene.selected_objects
if not selection:
    xray.log("Ничего не выделено")
```

### `scene.find(name: str) -> Object | None`

Ищет по имени средствами сцены SDK. Возвращает `None`, если объект не найден.
Не предполагает пользовательскую поддержку регулярных выражений или масок.

```python
obj = xray.scene.find("marker_01")
if obj is not None:
    xray.log("Найден:", obj.position)
```

### `scene.create(kind, name="", reference="", position=(0, 0, 0)) -> Object`

| `kind` | Создаваемая сущность | Особенности |
|---|---|---|
| `"object"` | Библиотечный объект сцены | Нужна существующая ссылка библиотеки |
| `"light"` | Источник света | Специализированные поля света не раскрыты |
| `"shape"` | Shape | Изначально содержит единичную коробку |
| `"glow"` | Glow | Дополнительные настройки через этот API не раскрыты |
| `"way"` | Way object | API редактирования точек маршрута пока отсутствует |

Пустое имя вызывает генерацию имени средствами редактора. Заданное имя
должно быть уникально в сцене. Создание может быть отклонено, если инструмент
объекта не доступен для редактирования.

```python
with xray.scene.transaction("Создать маркер"):
    marker = xray.scene.create("shape", name="marker_01", position=(0, 1, 0))
    marker.selected = True
```

Для библиотечного объекта `reference` соответствует реальному ресурсу в
библиотеке `$objects$`. Пример ниже требует предварительно заменить ссылку
на существующую в вашем SDK:

```python
# Путь/имя ресурса берётся из установленной библиотеки объектов.
library_reference = r"props\existing_model"
with xray.scene.transaction("Добавить библиотечный объект"):
    obj = xray.scene.create(
        "object",
        name="placed_model_01",
        reference=library_reference,
        position=(2, 0, 3),
    )
```

`scene.create` не импортирует внешние FBX/OBJ и не создаёт новый меш.
Параметр `reference` проверяется для `kind="object"`; для остальных типов
он не является способом назначить произвольный ресурс.

### `scene.transaction(label="Python operation")`

Возвращает контекстный менеджер группировки изменений. Подробная семантика
вложенности, отката и инвалидирования ссылок приведена в разделе 17.

## 16. Объекты и xray.Object

`Object` — лёгкая Python-обёртка проверяемого дескриптора. При чтении свойства
данные запрашиваются у редактора, а не берутся из постоянно актуальной копии.

| Член | Тип | Чтение | Запись |
|---|---|---|---|
| `handle` | `int` | Да | Технически Python-атрибут; не изменять |
| `name` | `str` | Да | Да |
| `position` | `tuple[float, float, float]` | Да | Да |
| `rotation` | `tuple[float, float, float]` | Да | Да |
| `scale` | `tuple[float, float, float]` | Да | Да |
| `selected` | `bool` | Да | Да |
| `visible` | `bool` | Да | Да |
| `class_id` | `int` | Да | Нет |
| `reference` | `str | None` | Да | Нет |
| `delete()` | Метод | — | Удаляет объект |

### Идентичность и время жизни

Дескриптор уникален в рамках текущего процесса. Он не сохраняется в файл
сцены и не подходит для обмена между процессами редакторов. Конструировать
`xray.Object(123)` вместо поиска объекта не следует: число не доказывает,
что объект существует.

После удаления, загрузки, очистки сцены, Undo/Redo и отката транзакции
получайте объекты заново. Переименование внешними средствами редактора
также может потребовать повторного поиска. Переименование через `obj.name`
обновляет внутреннюю запись дескриптора.

```python
name = obj.name
xray.ops.execute("COMMAND_UNDO")
# Старый obj больше не используется.
obj = xray.scene.find(name)
```

Равенство двух разных Python-обёрток не переопределено как равенство объектов
сцены. Для краткоживущих сравнений в одном состоянии сцены сравнивайте `handle`.
Для долговременных данных храните понятный ключ, например имя, с проверкой
коллизий и возможности переименования.

### `name`

Имена должны быть уникальны. Нативная проверка допускает от 1 до 200 байтов
после преобразования в кодовую страницу SDK. Сообщение ошибки использует
слово characters, но фактически проверяется длина нативной строки.
Перенос строки, табуляция, `\\`, `/`, `\x1f` запрещены; NUL не используйте
ни в одном аргументе строкового C ABI.

```python
obj.name = "marker_renamed"
```

Пограничное преобразование legacy-строк использует системную ANSI-кодировку
Windows. Python и JSON работают с Unicode/UTF-8, но это не делает все старые
имена ресурсов SDK полностью Unicode-совместимыми. Для идентификаторов
ресурсов переносимее латинские имена.

### `position`

Позиция `(x, y, z)` в системе координат редактора. Для подъёма в примерах
меняется компонент Y. Координаты задаются в единицах SDK; Python-API не
выполняет автоматическое преобразование масштаба единиц.

```python
x, y, z = obj.position
obj.position = (x + 2.0, y, z)
```

Нельзя изменить элемент кортежа `obj.position[0] = ...`. Назначайте весь вектор.
Нативные трансформации хранятся как `float`; большое Python-число может
оказаться непредставимым и быть отклонено после преобразования.

### `rotation`

Три компонента вращения в **радианах**. Это вектор вращения, используемый
редактором, не quaternion и не матрица. API не объявляет дополнительный
пользовательский порядок Euler сверх поведения нативного редактора.

```python
import math

rx, ry, rz = obj.rotation
obj.rotation = (rx, ry + math.radians(90), rz)
```

### `scale`

Три положительных компонента. Нулевой и отрицательный масштаб отклоняются.
Используйте конечные значения разумного размера.

```python
sx, sy, sz = obj.scale
obj.scale = (sx * 1.5, sy * 1.5, sz * 1.5)
```

### `selected`

Устанавливает выделение и обновляет сцену UI. Само изменение выделения
не вызывает `Changed()` и не создаёт отдельную запись Undo в этом backend.
Поэтому не полагайтесь на транзакцию как на средство отмены операции,
которая меняла только выделение.

```python
obj.selected = True
```

### `visible`

Показывает или скрывает объект. Считается изменением сцены; используется
механизм уведомления и сохранения Undo.

```python
obj.visible = False
```

### `class_id`

Числовой идентификатор класса SDK, доступный только для чтения. Публичного
Python-перечисления всех `OBJCLASS_*` API 1 не поставляет. Для расширений,
которым нужны конкретные значения, сверяйтесь с исходным enum и закрепляйте
совместимость с используемой сборкой.

### `reference`

Ссылка на библиотечный ресурс для Scene Object, иначе `None`. Только чтение.
Изменить модель существующего объекта присваиванием `reference` нельзя.

### `delete() -> None`

Удаляет объект из сцены. Его дескриптор становится недействительным сразу.
Перед удалением сохраните значения, которые ещё нужны для отчёта.

```python
name = obj.name
obj.delete()
xray.log("Удалён:", name)
```

Изменения заблокированных объектов и объектов групп без индивидуальной
редактируемости отклоняются. Не обходите это записью в память через ctypes.

## 17. Транзакции, Undo, Redo и откат

Транзакция сохраняет снимок сцены перед операцией. При успешном завершении
изменения группируются в одну запись Undo. При исключении сцена восстанавливается
из снимка, если backend зарегистрировал изменения.

```python
with xray.scene.transaction("Переместить выделение"):
    for obj in xray.scene.selected_objects:
        x, y, z = obj.position
        obj.position = (x + 1, y, z)
```

Операторы с `undo=True` и классы с `"UNDO"` в `bl_options` уже получают такую
обёртку. Повторная внутренняя транзакция допустима, но отдельного шага Undo
не создаёт.

### Вложенность

Вложенные контексты объединяются в одну внешнюю транзакцию. Если во внутреннем
контексте возникло исключение, общий контекст помечается неудачным, даже если
исключение затем перехвачено внутри внешнего блока:

```python
with xray.scene.transaction("Общая операция"):
    try:
        with xray.scene.transaction("Внутренняя часть"):
            raise ValueError("Нельзя продолжить")
    except ValueError:
        xray.log("Ошибка обработана, но транзакция всё равно будет откачена")
```

Если исключение перехвачено до выхода из любого транзакционного контекста,
оно не становится сигналом отката. Делайте намерение явным.

### Нативные команды внутри транзакции

Нативные сохранения Undo перехватываются и объединяются с общей операцией.
Это позволяет группировать поддерживаемые изменения через командный мост.
Но сами команды должны быть пригодны для запуска в текущем состоянии SDK.

Load, Clear, Undo и Redo инвалидируют объекты и не допускаются внутри активной
транзакции. Для них используйте оператор без автоматического Undo.

### Что транзакция не откатывает

- Запись файлов и сетевые операции Python.
- Переменные модулей и экземпляров панели.
- Содержимое `preferences` и Lua-состояние.
- Процессы или потоки, запущенные аддоном.
- Изменения, которые не участвуют в механизме снимка/уведомлений сцены.
- Отдельную историю выделения, если менялось только `selected`.

`label` передаётся при начале транзакции, но backend API 1 не сохраняет
его как отдельную расширенную метку истории. Не стройте интерфейс истории
на предположении, что SDK покажет эту строку пользователю.

Откат может пересоздать объекты. Даже если после отката объект с тем же
именем снова существует, старая обёртка не является допустимой ссылкой.

### Практика

Сначала проверьте параметры и сформируйте список работы, затем откройте
одну короткую транзакцию. Не держите её открытой между кадрами и не пытайтесь
растянуть контекстный менеджер через таймер: это мешает обычным Undo/Load
и усложняет восстановление сцены.

Вне транзакции изменения положения, масштаба, имени, видимости, создание
и удаление сохраняют Undo по отдельности. Для большого пакета это дороже
и менее удобно, чем одна общая операция.

## 18. События

```text
events.subscribe(event: str, callback) -> object
events.unsubscribe(token: object) -> None
```

Подписка возвращает непрозрачный токен. Callback принимает один аргумент —
payload события. Токен используйте для выборочной отписки; при отключении
аддона все его подписки удаляются автоматически.

| Имя | Payload | Когда поступает |
|---|---|---|
| `startup` | Строка редактора | После загрузки сохранённых активных аддонов |
| `shutdown` | Строка редактора | Перед отключением аддонов при закрытии |
| `command_executed` | Имя `COMMAND_*` | После выполнения наблюдаемой команды |
| `scene_loaded` | `"COMMAND_LOAD"` | Псевдоним события этой команды |
| `scene_saved` | `"COMMAND_SAVE"` | Псевдоним события этой команды |
| `scene_cleared` | `"COMMAND_CLEAR"` | Псевдоним события этой команды |
| `undo` | `"COMMAND_UNDO"` | Псевдоним события этой команды |
| `redo` | `"COMMAND_REDO"` | Псевдоним события этой команды |
| `selection_changed` | Список числовых дескрипторов | Изменение опрашиваемого выделения |

Пример:

```python
subscription = None


def on_saved(command_name):
    xray.log("Получено уведомление:", command_name)


def register():
    global subscription
    subscription = xray.events.subscribe("scene_saved", on_saved)


def unregister():
    global subscription
    if subscription is not None:
        xray.events.unsubscribe(subscription)
        subscription = None
```

### Важная семантика

Событие команды ставится в очередь, затем обрабатывается в цикле хоста.
Это уведомление о вызове наблюдаемой команды, не транзакционный журнал
и не доказательство успешного изменения файла. Например, команда Save
могла открыть диалог и быть отменена пользователем.

Команды, в имени которых есть `UPDATE`, `RENDER` или `REFRESH`, фильтруются.
Очередь команд ограничена 256 элементами; при переполнении новые события
не добавляются. Не используйте этот поток как безусловно полную историю.

`selection_changed` работает в Level Editor при наличии подписчиков.
Выделение проверяется приблизительно раз в 0,1 секунды. Первое уведомление
может отражать начальное состояние; payload — числа, а не `Object`.
Обработчику удобнее заново запросить `context.selected_objects`.

```python
def on_selection_changed(handles):
    names = [obj.name for obj in xray.context.selected_objects]
    xray.log("Сейчас выделено:", ", ".join(names))
```

Событие не повторяется новому подписчику задним числом. Если аддон включён
после старта SDK, он не получит уже прошедшее `startup`. Инициализацию
собственного состояния выполняйте и в `register()`.

Публичного `events.emit`, отмены команды из события, приоритетов подписчиков
и отдельных `before_*` событий в API 1 нет. Не подписывайтесь на выдуманные
имена в ожидании автоматического вызова.

Не запускайте из обработчика безусловно ту же команду, которую он наблюдает:
это создаст цикл уведомлений. Для обновления отчёта достаточно пометить
кеш устаревшим.

## 19. Таймеры

```text
timers.register(callback, first_interval: float = 0.1) -> object
timers.unregister(token: object) -> None
```

Callback вызывается без аргументов на основном потоке SDK. Возвращённое
конечное неотрицательное число означает интервал до следующего запуска.
`None` останавливает таймер. Исключение или неподходящее возвращённое
значение также прекращают его повторение.

```python
def update_report():
    xray.log("Редактор:", xray.context.editor)
    return 2.0


def register():
    xray.timers.register(update_report, first_interval=1.0)
```

Однократное отложенное действие:

```python
def next_frame():
    xray.log("Продолжение на основном потоке")
    return None


xray.timers.register(next_frame, first_interval=0.05)
```

`first_interval` не должен быть отрицательным или бесконечным. Ноль
допускается, но означает ближайшую обработку таймеров, а не синхронный
рекурсивный вызов. Для повторений применяется минимум 0,01 секунды.

В одном проходе выполняется не более 32 готовых таймеров. Выполненные
повторяющиеся таймеры перемещаются в конец очереди. Период — ориентир,
а не гарантия реального времени: кадр, занятый редактор или другой callback
могут задержать запуск. Таймеры обслуживаются и при потере фокуса окна,
пока обычный цикл редактора продолжает работать.

Для прекращения по состоянию:

```python
remaining = 3


def repeat_three_times():
    global remaining
    remaining -= 1
    xray.log("Осталось:", remaining)
    return 0.5 if remaining > 0 else None
```

Не передавайте `async def` как обычный callback в ожидании автоматического
await. Хост не запускает цикл asyncio и не ожидает coroutine. Если нужна
асинхронная подсистема, её жизненным циклом управляет сам аддон, а обращения
к редактору всё равно возвращаются на UI-поток.

## 20. Настройки аддонов

### `preferences.load() -> JSON`

Читает `<sdk_root>/settings/addons/<owner>.json`. Если файла нет,
возвращает `{}`. Некорректный JSON вызывает исключение; универсальной
проверки схемы содержимого нет.

### `preferences.save(value: JSON) -> None`

Сериализует значение в UTF-8 JSON с отступами. Сначала создаётся временный
файл, затем выполняется атомарная замена. Это предотвращает обычный сценарий
частично перезаписанного файла, но не обеспечивает объединение конкурирующих
правок двух процессов одного аддона.

```python
state = {"distance": 1.0, "prefix": "obj", "schema": 1}


def load_settings():
    try:
        value = xray.preferences.load()
    except (OSError, ValueError) as error:
        xray.log("Не удалось прочитать настройки:", error)
        return
    if not isinstance(value, dict):
        xray.log("Ожидался словарь настроек")
        return
    distance = value.get("distance", 1.0)
    if isinstance(distance, (int, float)):
        state["distance"] = float(distance)


def save_settings():
    xray.preferences.save(state)
```

Вызывайте эти методы из `register()` или callback своего аддона: путь
определяется текущим владельцем. В консоли используется `console.json`,
а не файл последнего выделенного аддона менеджера.

Не сохраняйте настройки из `draw()` каждый кадр. Кнопка «Сохранить» или
редкое отложенное сохранение уменьшают запись на диск. Добавляйте поле
версии схемы, если формат настроек будет развиваться.

### Состояние включения аддонов

`settings/addons.json` — отдельный файл менеджера. Пример:

```json
{
  "level": ["hello_sdk", "scene_tools"],
  "actor": ["hello_sdk"],
  "particle": [],
  "shader": []
}
```

Для каждого редактора хранится свой список. При сохранении менеджер
использует именованный Windows-мьютекс и перечитывает общий файл, чтобы
сохранить записи других редакторов. Личные настройки аддона по умолчанию
общие между редакторами; при необходимости храните внутри JSON словарь
по `context.editor`.

## 21. Консоль, журнал и разовый запуск

### `xray.log(*values: object) -> None`

Объединяет строковые представления значений через пробел. Сообщение
попадает в вывод Python Console и штатный журнал с префиксом `[Python]`.

```python
xray.log("Обработано", 12, "объектов")
print("Обычный print тоже перенаправлен в SDK")
```

`stdout` и `stderr` перенаправлены. Строки без перевода строки могут
буферизоваться; для явного завершения используйте `flush=True` у print
или `sys.stdout.flush()`. Очень длинный незавершённый фрагмент разбивается
механизмом потока после накопления более 8192 символов.

Окно консоли хранит до 1000 записей; это не бесконечный архив. **Clear output**
очищает видимый вывод, не удаляет переменные консоли и не отключает аддоны.
Буфер поля ввода консоли — 16384 байта вместе с завершающим NUL.
Для большого текста используйте `.xpy`-файл.

### Выражения и многострочный код

Консоль сначала пробует интерпретировать ввод как выражение. Если это
невозможно, выполняет как набор операторов. Непустой результат выражения
выводится через `repr`. Пространство имён сохраняется между запусками;
`xray` и `context` доступны изначально.

```python
[obj.name for obj in context.selected_objects]
```

```python
with xray.scene.transaction("Поднять из консоли"):
    for obj in context.selected_objects:
        x, y, z = obj.position
        obj.position = (x, y + 0.5, z)
```

### Run .xpy file

**Scripts → Run .xpy file...** выполняет файл как разовый скрипт с
`__name__ == "__main__"`, установленным `__file__` и доступным `xray`.
Это не установка: функция `register()` не вызывается автоматически.

```python
import xray


def main():
    xray.log("Сцена содержит:", len(xray.scene.objects))


if __name__ == "__main__":
    main()
```

Разовый запуск использует владельца console. Если он зарегистрирует
таймеры/панели, они не получают отдельной записи менеджера для отключения.
Для постоянного инструмента оформляйте настоящий аддон с жизненным циклом.

## 22. Мост Python → LuaJIT

`xray.lua` выполняет Lua-код в отдельном состоянии владельца. Его можно
использовать для совместных Python/Lua-инструментов и переноса небольших
Lua-алгоритмов. Это отдельная среда, а не доступ к глобальным переменным
игровой/server Lua VM.

### `lua.eval(expression: str) -> JSON`

Вычисляет Lua-выражение. На нативной стороне к нему добавляется `return (...)`.

```python
value = xray.lua.eval("2 + 3 * 4")
xray.log(value)  # 14
```

Не передавайте сюда последовательность Lua-инструкций; для неё существует
`execute`.

### `lua.execute(source: str) -> JSON`

Выполняет Lua-chunk. Используется первое возвращаемое значение; без return
результат `None`. Состояние сохраняется между обращениями того же владельца.

```python
xray.lua.execute("counter = (counter or 0) + 1")
xray.log(xray.lua.eval("counter"))

result = xray.lua.execute('return {name="пример", values={1, 2, 3}}')
assert result == {"name": "пример", "values": [1, 2, 3]}
```

### `lua.call(name: str, *arguments: JSON) -> JSON`

Вызывает именованную функцию, передавая преобразованные аргументы.
Допускается имя вида `function_name` или `module.function_name`.
Правило: `[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*`.
Lua-синтаксис методов с двоеточием в `name` не поддерживается.

```python
xray.lua.execute("""
tools = {}
function tools.offset(p, distance)
    return {p[1], p[2] + distance, p[3]}
end
""")

position = xray.lua.call("tools.offset", [1, 2, 3], 0.5)
assert position == [1, 2.5, 3]
```

Аргументы преобразуются обёрткой в Lua-литералы, затем вычисляется вызов.
Строки кодируются UTF-8 и экранируются. Не собирайте выражения вручную из
неэкранированного пользовательского текста.

### `lua.reset() -> None`

Удаляет Lua-состояние текущего владельца. Следующий вызов создаст новое.
Глобальные переменные и определённые функции будут потеряны.
То же происходит при Disable/Reload и завершении редактора.

### Преобразование типов

| Python → Lua | Представление |
|---|---|
| `None` | `nil` |
| `bool` | `true` / `false` |
| `int`, конечный `float` | Числовой литерал |
| `str` | UTF-8 строка |
| `list`, `tuple` | Таблица с индексами от 1 |
| `dict` со строковыми ключами | Таблица полей |

| Lua → Python | Представление |
|---|---|
| `nil` | `None` |
| boolean | `bool` |
| Конечное число | `int` либо `float` после JSON-декодирования |
| UTF-8 string | `str` |
| Плотная таблица 1..N | `list` |
| Таблица только со строковыми ключами | `dict` |
| Пустая таблица | `{}` |

LuaJIT использует числовую семантику своей среды: произвольно большие Python
целые не гарантируют точный обмен. Для точных больших ID передавайте строки.
Дробное значение `1.0` также не обязано вернуться именно как Python float.

Пустой Python-список после передачи и возврата может стать `{}`, потому что
пустая Lua-таблица не содержит признака массива. `nil` внутри Lua-массива
удаляет элемент; разреженные и смешанные таблицы не являются переносимым
форматом обмена. Используйте явно описанную схему данных без дыр.

Циклы, чрезмерная вложенность (предел проверки — глубина 16), функции,
userdata, потоки Lua и неподдерживаемые ключи отклоняются. Нечисловые
значения NaN/Infinity не передаются. Lua-строки должны быть корректным UTF-8.

### Функции SDK внутри Lua

```lua
sdk.log("Сообщение из Lua")
local reply = sdk.command("COMMAND_NAME", 0, 0)
return reply
```

`sdk.log` передаёт первый аргумент как текст в журнал. Это не полный
эквивалент Python `log(*values)`.

`sdk.command` вызывает командный мост. Ответ — **строка JSON-оболочки**,
например `{"ok": 1}`, а не непосредственно число или Lua-таблица.
Ошибку команды нужно прочитать из оболочки. На стороне Python:

```python
import json

# Выберите подходящую команду из xray.ops.list() и проверьте её семантику.
# raw = xray.lua.execute('return sdk.command("COMMAND_NAME", 0, 0)')
# reply = json.loads(raw)
# if "error" in reply:
#     raise RuntimeError(reply["error"])
```

Для команд из Python предпочтительнее `xray.ops.execute`: его валидация
аргументов и обработка ошибок удобнее прямого Lua-вызова.

### Время и изоляция

У каждого включённого аддона собственное Lua-состояние. Консоль и разовые
скрипты разделяют console-состояние. Изоляция переменных не является
песочницей: Lua открывает обычные библиотеки LuaJIT.

JIT отключён, чтобы instruction hook мог прервать длительный Lua-код.
Бюджет выполнения — около двух секунд, проверка через каждые 10000
инструкций. Блокирующий нативный вызов этим механизмом не прерывается.
Синтаксические ошибки, runtime-ошибки и ошибки преобразования становятся
Python RuntimeError.

## 23. Мост Python → C++ и ABI

Это раздел для разработчиков самого SDK и нативных расширений. Обычный
аддон должен использовать `xray.scene`, `xray.ops` и другие обёртки.

### Экспортируемая функция

```cpp
extern "C" const char* __cdecl SDKScriptCall(
    const char* operation,
    const char* text,
    double x,
    double y,
    double z
);
```

Функция экспортируется из `SDKRuntime.dll`. Точное объявление типа указателя
есть в `SDKScriptABI.h`. Поставка рассчитана на Windows x64.
Входные строки — UTF-8 и NUL-terminated. Ответ принадлежит вызывающему потоку:

```json
{"ok": {"example": 1}}
```

```json
{"error": "Описание ошибки"}
```

Указатель ответа действителен до следующего вызова моста в том же потоке.
Скопируйте ответ до повторного вызова, не освобождайте его самостоятельно.
В Python `ctypes.c_char_p` получает копию байтов для декодирования JSON.

Python-обёртка использует `ctypes.PyDLL`, сохраняя GIL при вызове редактора.
Ошибка в JSON-оболочке превращается в RuntimeError. Восстанавливаемые
нативные исключения преобразуются мостом; это не обещание восстановить
процесс после любого повреждения памяти.

### Поле text и числовые параметры

Операции с несколькими строковыми полями соединяют их ASCII Unit Separator
`\x1f` (U+001F). При использовании публичных обёрток поля с NUL/разделителем
отклоняются там, где применяется `_join`. Не используйте NUL ни в каком
строковом аргументе C ABI: C-строка на нём заканчивается.

`x`, `y`, `z` — конечные double. В зависимости от операции это координаты,
состояние checkbox, значение/шаг или границы slider. В backend трансформаций
они преобразуются в float.

ручное управление чужими владельцами через `owner_remove` не является
поддерживаемой точкой расширения аддона.

### Кодирование параметров команды

Каждый параметр начинается с `s` для строки или `i` для uint32:

```text
COMMAND_EXAMPLE\x1fsстроковый параметр\x1fi42
```

Не путайте видимую запись `\x1f` в документации с реальным байтом 0x1F.
Обычный `.xpy`-код не должен вручную собирать эти строки.

### Пример получения указателя в C++

```cpp
#include <Windows.h>
#include <string>
#include "SDKScriptABI.h"

std::string ReadSdkContextOnUiThread()
{
    HMODULE runtime = GetModuleHandleW(L"SDKRuntime.dll");
    if (!runtime)
        return {};
    auto call = reinterpret_cast<SDKScriptCallFunction>(
        GetProcAddress(runtime, "SDKScriptCall"));
    if (!call)
        return {};
    const char* reply = call("context", "", 0, 0, 0);
    return reply ? std::string(reply) : std::string();
}
```

Функцию из примера нужно вызывать на потоке редактора после запуска хоста.
После JSON-декодирования проверяйте `api_version == 1`.

## 24. Расширение API на стороне C++

Общий хост описан в `Editors/XrECore/Editor/SDKScriptHost.h`:

```cpp
namespace SDKScript
{
    using Backend = std::string(*)(
        const std::string& operation,
        const std::string& text,
        double x, double y, double z);

    void SetBackend(Backend backend);
}
```

Backend возвращает сериализованное **JSON-значение**, например `"null"`,
`"[1,2]"` или объект, а общая экспортируемая функция добавляет оболочку
`{"ok": ...}`. В случае ошибки backend бросает подходящее C++-исключение.

Backend регистрируется до первого кадра Python. В API 1 у хоста один
backend-указатель; повторный `SetBackend` заменяет его. Это интерфейс
разработки редактора, не реестр динамических C++-аддонов.

Эталон привязок сцены: `Editors/LevelEditor/Kernel/SDKScriptScene.cpp`.
Рекомендуемая последовательность расширения:

1. Определить публичную функцию и редакторы, где она поддерживается.
2. Добавить нативную операцию с проверкой сцены, аргументов и блокировок.
3. Определить кодировку строк и JSON-результат.
4. Для мутаций провести штатные уведомления и участие в Undo.
5. Добавить Python-обёртку в `python/xray/__init__.py`.
6. Добавить сигнатуру в `api/xray.pyi`.
7. Обновить этот справочник, ограничения и примеры.
8. Проверить успешный путь, неверные аргументы, старые handles, Undo и откат.

Не возвращайте адрес C++-класса как «быстрый объект» Python. Такой подход
привязывает аддон к layout, времени жизни и версии нативного класса.
Дескрипторы должны проверяться при каждом разрешении.

Если добавляется поле света или материала, явно решите, что происходит
при неподходящем `class_id`, блокировке объекта, отсутствии ресурса,
изменении сцены и сериализации. Одного присваивания нативному полю
обычно недостаточно: нужно обновить UI и механизм изменений редактора.

Общие функции хоста `Tick`, `Draw`, `Shutdown`, `CommandEvent`, `Quote`,
`FromUTF8`, `ToUTF8` предназначены для интеграции редакторов. Вызывать
их напрямую из `.xpy` как публичные функции не требуется.

## 25. Потоки, время исполнения и производительность

### Основной поток

Публичные обращения к редактору выполняются на UI-потоке. Мост проверяет
его ID. Из фонового потока исключение выдаётся даже для чтения сцены.
Исключение предусмотрено для `log`: сообщения попадают в защищённую
очередь и позже выводятся основным потоком.

Регистрация таймеров и манипуляции Python-реестрами также не являются
задокументированным потокобезопасным интерфейсом. Создавайте таймер на
основном потоке, а результаты фоновой работы передавайте через
`queue.Queue` и читайте из этого таймера.

Сам встроенный хост не предоставляет планировщик фоновых задач и не
обещает освобождать GIL во всех состояниях бездействия. Пример очереди —
шаблон обмена результатом, а не гарантия высокой производительности
произвольного Python-thread workload. Проверяйте конкретную задачу.

### Бюджеты callback

| Контекст | Бюджет проверки Python-кода |
|---|---|
| Импорт + `register()` | 5 секунд |
| Python-оператор | 5 секунд |
| Python Console / разовый `.xpy` | 5 секунд |
| Отрисовка панели | 0,25 секунды |
| Обработчик события | 0,25 секунды |
| Callback таймера | 0,25 секунды |
| `unregister()` через общий guard | 2 секунды |

При восстановлении активных аддонов стартовый внешний guard дополнительно
имеет бюджет 8 секунд; вложенные callbacks контролируются собственными
бюджетами. Трассировщик проверяет время при событиях выполнения Python,
поэтому это не жёсткий независимый watchdog процесса.

Время внутри публичного нативного вызова исключается из Python-бюджета.
Это позволяет легитимной записи Undo занять больше времени без ложного
Python timeout. Но медленный нативный вызов всё равно блокирует интерфейс.
Нативные библиотеки и блокирующий I/O не прерываются этим трассировщиком.

После трёх ошибок callback владелец-аддон автоматически отключается.
Счётчик сбрасывается при успешном новом включении. Не используйте исключения
каждого кадра как обычный способ сообщить «объект пока не выбран».

### Как уменьшать стоимость

- Запрашивайте список выделения один раз в операции, а не в каждой итерации.
- Чтение каждого свойства `Object` вызывает мост; кешируйте данные для отчёта.
- Изменяйте пакет объектов в одной транзакции.
- Не делайте полный экспорт сцены из `draw()`.
- Не пишите настройки и журналы каждый кадр без необходимости.
- Для чистых вычислений сначала сформируйте обычные Python-данные, затем
  примените результат к сцене.
- Делите длительную работу на короткие таймерные этапы, если допустимы
  отдельные шаги Undo. Не держите одну транзакцию между этапами.

### Доступ к системе

Аддон имеет обычные права процесса SDK на файлы, сеть и нативные библиотеки.
API не предоставляет отдельные разрешения аддонов и не является песочницей.
Это техническая модель исполнения, а не дополнительный режим Python.

## 26. Обработка ошибок и диагностика

| Симптом | Вероятная причина | Что проверить |
|---|---|---|
| Аддона нет в списке | Не та папка, нет манифеста пакета, скрытое имя | `addons.directory`, Refresh, структуру |
| Запись Invalid | Ошибка JSON/Python AST/ID/entry | Текст ошибки и буквальные метаданные |
| Unsupported add-on API version | Несовместимое поле версии | `api_version: 1` |
| Add-on does not support ... | Текущего редактора нет в editors | Манифест и `context.editor` |
| Missing dependency | Не установлен нужный ID | `requires`, список менеджера |
| Circular add-on dependency | Цикл в requires | Граф зависимостей |
| Operator already registered | Повторный ID или регистрация | Единый register и уникальные ID |
| UI widgets may only be used... | Виджет вызван вне draw | Место вызова UI |
| Scene is unavailable or locked | Нет редактируемой сцены | Состояние Level Editor |
| Invalid or expired object handle | Старая ссылка | Повторный find/перечисление |
| Object was deleted, renamed or replaced | Объект изменён вне обёртки | Имя, состояние сцены |

| Non-finite... / Invalid transform | NaN/Infinity/переполнение float | Числа и диапазоны |
| Load, clear and Undo are not allowed... | Команда внутри транзакции | `undo=False` |
| Editor lifecycle commands cannot run... | Прямой Quit/Destroy | `app.request_exit()` |
| The editor API must be called on the UI thread | Вызов из worker | Очередь и таймер |
| Python callback exceeded... | Слишком длинный Python-callback | Разделить работу |

| LuaJIT runtime is unavailable | Нет нужной DLL | `bins/LuaJIT.dll` |

| Unknown editor command | Имя отсутствует в редакторе | `ops.list()` |

### Где исключение проходит наружу

Прямой вызов `obj.position = ...` внутри вашего кода выдаёт исключение
этому коду. Внешняя оболочка callback затем перехватывает необработанное
исключение, выводит traceback и учитывает ошибку владельца.

```python
obj = xray.scene.find("optional_marker")
if obj is None:
    xray.log("Маркер отсутствует — операция пропущена")
else:
    try:
        obj.position = (0, 0, 0)
    except RuntimeError as error:
        xray.log("Не удалось изменить объект:", error)
```

Не подавляйте все исключения без сообщения: это скрывает частично
выполненную операцию. Если нужна атомарность, пусть ошибка выйдет из
транзакции, а сообщение формируется снаружи.

```python
try:
    with xray.scene.transaction("Безопасное изменение"):
        obj = xray.scene.find("required_marker")
        if obj is None:
            raise ValueError("Обязательный маркер не найден")
        obj.position = (0, 2, 0)
except (ValueError, RuntimeError) as error:
    xray.log("Операция отменена:", error)
```

### Поведение при закрытии

После начала Shutdown большинство операций моста запрещено. Сообщение
`Editor is shutting down` в обработчике shutdown часто означает, что
аддон пытается прочитать сцену слишком поздно. Сохраняйте нужные данные
заранее, а на закрытии освобождайте собственные ресурсы.

### 27.5. Привязать позиции к сетке

```python
import math
import xray
```

### 27.9. Двухфазное переименование без коллизий внутри выделения

При переименовании `obj_1 → obj_2` и `obj_2 → obj_3` прямой проход может
встретить ещё занятое имя. Сначала назначьте временные уникальные имена,
потом окончательные. При конфликте с объектом вне выделения отмените
операцию до начала изменений.

```python
import uuid
import xray

selection = xray.scene.selected_objects
selected_handles = {obj.handle for obj in selection}
final_names = [f"item_{index:04d}" for index in range(1, len(selection) + 1)]

for name in final_names:
    existing = xray.scene.find(name)
    if existing is not None and existing.handle not in selected_handles:
        raise ValueError("Имя занято объектом вне выделения: " + name)

nonce = uuid.uuid4().hex[:16]
with xray.scene.transaction("Переименовать выделение"):
    for index, obj in enumerate(selection):
        obj.name = f"tmp_{nonce}_{index}"
    for obj, name in zip(selection, final_names):
        obj.name = name
```

Порядок нумерации здесь определяется порядком выделения, возвращённым API.
Если нужен воспроизводимый порядок, отсортируйте список, например по
исходному имени, до формирования `final_names`.

### 27.13. Применить снимок к существующим объектам

Ниже используется файл предыдущего рецепта. Валидация выполняется до
изменений, а назначение свойств — внутри одной транзакции.

```python
import json
import math
import xray


def vector(value, field, positive=False):
    if not isinstance(value, list) or len(value) != 3:
        raise ValueError("Ожидался вектор из трёх значений: " + field)
    if any(isinstance(v, bool) or not isinstance(v, (int, float)) for v in value):
        raise ValueError("Компоненты должны быть числами: " + field)
    result = tuple(float(v) for v in value)
    if not all(math.isfinite(v) for v in result):
        raise ValueError("Вектор содержит неконечные значения: " + field)
    if positive and not all(v > 0 for v in result):
        raise ValueError("Масштаб должен быть положительным")
    return result


filename = xray.context.sdk_root / "settings" / "selection_transforms.json"
data = json.loads(filename.read_text(encoding="utf-8"))
if not isinstance(data, dict) or data.get("format") != "xray_transform_snapshot":
    raise ValueError("Неизвестный формат снимка")
if data.get("version") != 1 or data.get("rotation_unit") != "radian":
    raise ValueError("Несовместимая версия или единица вращения")
if not isinstance(data.get("objects"), list):
    raise ValueError("Отсутствует список объектов")

work = []
seen = set()
for item in data["objects"]:
    if not isinstance(item, dict) or not isinstance(item.get("name"), str):
        raise ValueError("Некорректная запись объекта")
    name = item["name"]
    if name in seen:
        raise ValueError("Повторное имя в снимке: " + name)
    seen.add(name)
    obj = xray.scene.find(name)
    if obj is None:
        raise ValueError("Не найден объект: " + name)
    visible = item.get("visible", True)
    if not isinstance(visible, bool):
        raise ValueError("visible должен быть bool")
    work.append((obj, vector(item["position"], "position"),
                 vector(item["rotation"], "rotation"),
                 vector(item["scale"], "scale", positive=True), visible))

with xray.scene.transaction("Восстановить трансформации"):
    for obj, position, rotation, scale, visible in work:
        obj.position = position
        obj.rotation = rotation
        obj.scale = scale
        obj.visible = visible

xray.log("Восстановлено:", len(work))
```

Отсутствующие объекты намеренно не создаются: снимок не содержит достаточно
данных для восстановления произвольного класса.

### 27.16. Отложить обновление после серии событий

Если отчёт дорогой, обработчик события может только выставлять флаг.
Таймер обновляет его один раз после накопившихся изменений.

```python
import xray

dirty = True
summary = ""


def mark_dirty(payload):
    global dirty
    dirty = True


def refresh_if_needed():
    global dirty, summary
    if dirty:
        dirty = False
        summary = f"Выбрано объектов: {len(xray.context.selected_objects)}"
        xray.log(summary)
    return 0.5


def register():
    xray.events.subscribe("selection_changed", mark_dirty)
    xray.events.subscribe("scene_loaded", mark_dirty)
    xray.events.subscribe("undo", mark_dirty)
    xray.events.subscribe("redo", mark_dirty)
    xray.timers.register(refresh_if_needed, first_interval=0.1)


def unregister():
    pass
```

Этот фрагмент предназначен для аддона с `editors: ["level"]`.

### 27.17. Обмен данными с внешним вычислением

Для тяжёлой внешней задачи можно подготовить обычные данные на UI-потоке,
обработать их отдельным процессом и применить результат позже. Не передавайте
`Object` или handle как адрес памяти во внешний процесс. Передавайте имена
и значения, а перед применением заново найдите объекты и проверьте, что
сцена не изменилась неожиданным образом.

Минимальная схема очереди для уже существующего производителя результата:

```python
from queue import Queue, Empty
import xray

results = Queue()


def poll_results():
    processed = 0
    while processed < 8:
        try:
            message = results.get_nowait()
        except Empty:
            break
        processed += 1
        xray.log("Получен результат:", message)
    return 0.1


def register():
    xray.timers.register(poll_results, first_interval=0.1)
```

Запуск/остановка производителя и управление процессом относятся к логике
самого аддона. Таймер не делает вычисление фоновым автоматически.

### 27.18. Вынести математическую функцию в Lua

## 28. Полный пример аддона

Ниже законченный однофайловый аддон `workspace_tools_ru.xpy`. Он добавляет
панель, операции перемещения и привязки к сетке, создание Shape-маркера,
сохранение настроек и счётчик выделения. Мутации выполняются через
операторы с автоматическими транзакциями. Сохранение настроек не создаёт
Undo сцены.

Сохраните код в `<sdk_root>/addons/workspace_tools_ru.xpy`, обновите список
и включите аддон в Level Editor.

```python
addon_info = {
    "id": "workspace_tools_ru",
    "name": "Инструменты рабочего места",
    "version": "1.0.0",
    "api_version": 1,
    "description": "Смещение, сетка, маркеры и настройки: пример API 1",
    "editors": ["level"],
    "requires": [],
}

import math
import xray

state = {
    "offset": 1.0,
    "grid": 0.5,
    "marker_size": 0.25,
    "selected_count": 0,
    "status": "Готово",
}


def positive_number(value, fallback):
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        return fallback
    value = float(value)
    return value if math.isfinite(value) and value > 0 else fallback


def load_settings():
    try:
        value = xray.preferences.load()
    except (OSError, ValueError) as error:
        xray.log("Настройки не прочитаны:", error)
        return
    if not isinstance(value, dict):
        return
    offset = value.get("offset", 1.0)
    if isinstance(offset, (int, float)) and not isinstance(offset, bool):
        offset = float(offset)
        if math.isfinite(offset):
            state["offset"] = offset
    state["grid"] = positive_number(value.get("grid"), 0.5)
    state["marker_size"] = positive_number(value.get("marker_size"), 0.25)


def update_selection(payload=None):
    state["selected_count"] = len(xray.context.selected_objects)


class MoveUp(xray.Operator):
    bl_idname = "workspace_tools_ru.move_up"
    bl_label = "Переместить по Y"
    bl_shortcut = "CTRL+SHIFT+U"

    def execute(self, context):
        distance = state["offset"]
        if not math.isfinite(distance):
            raise ValueError("Смещение должно быть конечным")
        objects = context.selected_objects
        for obj in objects:
            x, y, z = obj.position
            obj.position = (x, y + distance, z)
        state["status"] = f"Перемещено объектов: {len(objects)}"
        xray.log(state["status"])


class SnapToGrid(xray.Operator):
    bl_idname = "workspace_tools_ru.snap"
    bl_label = "Привязать к сетке"

    def execute(self, context):
        step = state["grid"]
        if not math.isfinite(step) or step <= 0:
            raise ValueError("Шаг сетки должен быть положительным")
        objects = context.selected_objects
        for obj in objects:
            obj.position = tuple(round(v / step) * step for v in obj.position)
        state["status"] = f"Привязано объектов: {len(objects)}"


class CreateMarker(xray.Operator):
    bl_idname = "workspace_tools_ru.create_marker"
    bl_label = "Создать Shape-маркер"

    def execute(self, context):
        size = state["marker_size"]
        if not math.isfinite(size) or size <= 0:
            raise ValueError("Размер маркера должен быть положительным")
        marker = xray.scene.create("shape", position=(0, 0, 0))
        marker.scale = (size, size, size)
        marker.selected = True
        state["status"] = "Создан: " + marker.name
```

## 29. Упаковка, распространение и обновление

### Один файл

Передайте пользователю `.xpy`. После Install менеджер размещает его под
именем `<id>.xpy` и показывает выключенным. Можно установить и ZIP с одним
таким файлом.

### Пакет

Допускаются две структуры ZIP:

```text
archive.zip
  addon.json
  __init__.xpy
  helpers.xpy
```

```text
archive.zip
  my_addon/
    addon.json
    __init__.xpy
    helpers.xpy
```

Если `addon.json` нет непосредственно в корне распакованного архива,
в корне должен находиться ровно один элемент — пакетная папка или один
`.xpy`. Не добавляйте рядом отдельную папку документации/служебные файлы
архиватора, нарушающие эту структуру. Документацию и ресурсы пакета
размещайте внутри его папки.

Ресурсы не обязаны иметь расширение `.xpy`: JSON, изображения, Lua-тексты
и другие данные могут храниться рядом. `.xpy` — формат пользовательского
Python-исходника, а не всех файлов архива.

### Проверки установки

Установщик отклоняет выход за папку распаковки, абсолютные пути,
символьные ссылки в архиве, слишком большой архив и некорректную точку
входа. Эти проверки не оценивают поведение самого Python-кода после
включения. При ручном копировании следите за теми же правилами структуры.

### Обновление

Для разработки используйте правку существующих файлов и Reload.
Для установки нового дистрибутива с уже занятым ID перезапись запрещена:

1. Отключите зависящие аддоны.
2. Отключите и удалите старую версию через менеджер.
3. Установите новый архив.
4. Включите аддон и затем его потребителей.
5. Проверьте миграцию собственного формата настроек.

Удалённая версия остаётся в `settings/addon-trash`. Прежние настройки
в `settings/addons/<id>.json` могут быть прочитаны новой версией, поэтому
важно проверять схему данных.

### Распространение среды Python

Исходный установщик SDK — `SDKRuntime/Scripting/InstallScripting.ps1`.
Он устанавливает частную среду Python, пакет `xray`, типы, API-документы
и выключенные примеры. Для установленного SDK используется команда:

```powershell
& '...\xray-sdk-0.4-Farkashed-Edition\SDKRuntime\Scripting\InstallScripting.ps1' `
    -SdkRoot '...\X-Ray SDK'
```

Можно передать `-RuntimeArchive` с локальным архивом. Установщик
проверяет закреплённый SHA256 и Authenticode-подпись Python DLL.
Поставка Python должна соответствовать версии, ожидаемой нативным хостом;
простое переименование другой Python DLL не обеспечивает совместимость.

При обычной сборке SDKRuntime цель `StageSdkScripting` копирует актуальные
Python-обёртки, файл типов и содержимое папки `api` в output. Она не
скачивает среду Python автоматически. Финальная установка runtime
остаётся задачей установщика.

## 30. IDE, типизация и проверка примеров

Для IDE `.xpy` нужно связать с языком Python. Например, в конфигурации
VS Code-подобного редактора:

```json
{
  "files.associations": {
    "*.xpy": "python"
  },
  "python.analysis.extraPaths": [
    ".../X-Ray SDK/bins/scripting"
  ]
}
```

Эти параметры относятся к IDE, а не к SDK. Наличие `extraPaths` помогает
найти пакет `xray` и `__init__.pyi`; поддержка анализа нестандартного
расширения зависит от конкретного языкового сервера.

`api/xray.pyi` удобно открывать как краткий перечень API; для разрешения
`import xray` IDE обычно удобнее направить на родителя пакета
`bins/scripting`, где установлен `xray/__init__.pyi`.

### Синтаксическая проверка вне редактора

Проверить синтаксис `.xpy` можно без импорта `xray` и выполнения аддона:

```python
import ast
from pathlib import Path

path = Path(r"E:\X-Ray SDK\addons\my_tools.xpy")
ast.parse(path.read_text(encoding="utf-8-sig"), filename=str(path))
print("Синтаксис корректен")
```

Это проверяет только грамматику. Наличие команды, доступность сцены,
правильность handle и поведение Undo проверяются в редакторе.

### Проверка поведения аддона

1. Включение не должно оставлять дубли после Disable → Enable.
2. Reload должен применять новый исходник дочернего `.xpy`.
3. Операция должна корректно работать при пустом выделении.
4. Ошибка одного объекта не должна оставлять неожиданные частичные правки.
5. Undo/Redo должны восстанавливать ожидаемое состояние сцены.
6. Старые ссылки после Undo не должны использоваться повторно.
7. Выключение должно удалить меню, панель, таймеры и подписки аддона.
8. Настройки должны иметь значения по умолчанию и проверку структуры.
9. Для зависимостей нужно проверить отсутствие и цикл requires.
10. Аддон только для сцены должен ограничить `editors` значением `level`.

### Существующие проверки реализации

В исходниках находятся `tests/test_addons.py` и `tests/native_smoke.xpy`.
Python-набор проверяет загрузку, зависимости, очистку, Reload, таймеры,
установку и опасные пути ZIP. Нативный набор проверяет реальное
взаимодействие с Level Editor, дескрипторы, транзакции, Undo/Redo и Lua.

Нативный smoke-тест изменяет тестовую сцену и запрашивает закрытие
редактора. Запускайте его в отдельной тестовой копии SDK; это внутренний
интеграционный тест, не обычный пользовательский пример аддона.

| `.py` аддон | `.xpy` аддон | Python-семантика сохранена |

облегчают знакомый стиль объявления, но не включают остальную архитектуру

получает свойства через RNA, `draw()` не имеет `self.layout`.

Для переноса аддона сначала выделите независимые алгоритмы Python,
затем замените доступ к данным и UI на `xray`. Возможности, которым
не соответствует API SDK, требуют новых нативных привязок.

## 32. Ограничения и технические особенности API 1

Этот перечень помогает не принимать предполагаемые функции за уже
реализованные.

### Модель данных

- Объектный API сцены реализован только для Level Editor.
- Нет публичной коллекции вершин, полигонов, UV, материалов и нод.
- Нет специализированных полей спавна, параметров света и точек Way.
- Создаваемый `object` ссылается на уже существующий ресурс библиотеки.
- Нет публичного метода duplicate/copy произвольного объекта.
- Нет универсального постоянного UUID сцены: handle действует в процессе.
- Нет публичной камеры, viewport draw-handler и инструмента манипулятора.
- `selected` не образует самостоятельную Undo-историю этого backend.

### Команды и события

- Список команд не содержит описания аргументов.
- Некоторые команды имеют отложенное поведение.
- События команд фильтруются и имеют ограниченную очередь.
- События scene_saved/scene_loaded — отображение имён команд, не отдельная
  гарантия успешной операции ввода/вывода.
- Нельзя остановить команду возвратом из обработчика события.
- Не поддерживаются пользовательский emit и приоритеты подписчиков.

### Интерфейс

- Панель рисуется средствами фиксированного набора `xray.ui`.
- Нет прямого доступа к ImGui, встроенного webview или Blender layout API.
- Текстовый input ограничен байтовым буфером.
- Горячие клавиши ограничены модификаторами и буквой.
- Класс панели/оператора создаётся один раз при регистрации, а не как
  полноценный набор типовизированных свойств редактора.

### Выполнение и зависимости

- Это встроенный CPython, а не преобразователь исходника в C++ или Lua.
- Зависимости requires разрешаются по ID без диапазонов версий и загрузки.
- Перезагрузка не управляет жизненным циклом произвольных внешних ресурсов.
- Фоновые потоки не могут напрямую читать или менять сцену.
- Ограничение времени Python не является независимым watchdog для native I/O.
- Lua-состояния не разделяют игровые/server глобальные переменные.
- Отключение класса через перестройку владельца сбрасывает его Lua-состояние.
- Для полностью переносимых legacy-имён учитывайте системную кодовую страницу.

### Перечень практически важных лимитов

| Что ограничивается | Текущее значение |
|---|---|
| ID аддона | 1–64 символа, правило `[a-z][a-z0-9_]{0,63}` |
| Имя объекта | 1–200 байтов после нативного преобразования |
| Нативный целочисленный аргумент команды | uint32 |
| Видимый input_text: входная строка | До 4094 байтов UTF-8 |
| Буфер ввода Python Console | 16384 байта вместе с NUL |
| Видимый журнал Python Console | До 1000 записей |
| Очередь логов из фонового потока | До 1000 ожидающих записей |
| Очередь наблюдаемых команд | До 256 событий |
| Готовые таймеры за проход | До 32 callback |
| Минимальный повтор таймера | 0,01 секунды |
| Шаг обслуживания хоста | Приблизительно не чаще 16 мс |
| Опрос выделения | Приблизительно раз в 0,1 секунды |
| Автоотключение аддона | После 3 ошибок callback |
| ZIP | 1024 элемента, 32 МиБ заявленного распакованного размера |
| Lua execution hook | Около 2 секунд, шаг 10000 инструкций |
| Рекурсивное преобразование Lua | Проверка глубины 16 |

Это характеристики реализации, не обещание точного тайминга реального времени.
Бюджеты разных видов callback перечислены в разделе 25.
